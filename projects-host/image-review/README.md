## Learning from decisions

Open **Learn from your choices → Update filter** after at least 200 current decisions, including 50 Meme and 50 Not meme. Learning runs on the NAS without this PC. It calibrates the existing refinement rank cutoff; it does not retrain the SigLIP image encoder. Skips and undone labels are excluded. A deterministic stratified 20% holdout (at least ten of each label) stays out of threshold fitting. A candidate activates only when balanced accuracy improves by at least five percentage points over both the original zero cutoff and any active cutoff, without reducing either class recall. Validation is preliminary and collection-specific: repeated updates reuse some holdout examples, and near-duplicate images can make results optimistic. Spot-check both likely bands and new collections.

An accepted cutoff changes **Most uncertain** sorting and the future-score API; existing bands, raw scores, saved labels, images and organization folders are preserved. A rejected update retains any valid earlier filter. Correcting or undoing a label used in training disables that filter until the labels match again or another update succeeds. Training and labels live in the same persistent NAS SQLite database and are excluded from releases.

Owner-only routes: `GET api/learning`, `POST api/learning/train` with `{}`, and `POST api/learning/predict` with `{"score_schema":"mungoon-refinement-rank-v1","items":[{"sha256":"<original hash>","score":0.1}]}`. Future scores must come from the same `rank_score` calculation used by refinement v1; arbitrary model scores are incompatible. Prediction returns adjusted margins and suggestions, honoring existing human labels by hash. It never writes decisions or moves files. New images still need their original image-scoring pass; this endpoint is the learned final decision step. `check_future_scores.py input.json output.json` applies that endpoint using the existing signed owner helper, refusing existing output files. No image upload or external AI service is introduced.

## People first, then memes; private adult-content review

The default **1 · Tag people** pass covers all organized images. Add a name/nickname and manually select each person in an image, optionally marking **Other people are present**. **No people**, skip and per-pass undo are available. Names are entered by the owner; there is no face recognition, face matching, automatic person propagation or identity-based meme classification.

Choose **Review tagged people for memes →** to enter **2 · Review memes** in the combined **Likely memes + Borderline** queue. **Only these people** accepts one or more manually tagged names (any selected person matches). Alternatively choose **Memes + Likely memes + Borderline** to include the original automatically organized Memes folder. Filters combine person tags, people-review status, source queue and adult-content labels. **Other people present** works for group photos with both named and other people.

**Adult-content review** opens the automatic **Likely adult + Uncertain** subset, with **Highest adult-content score** first. A pinned open-source NSFW model has scanned the available collection. Machine suggestions stay separate from the owner's Adult content / Not adult / Skip labels. **Adult-content filter → Marked adult content** clears the machine filter and returns all manually flagged images, including model misses. All images, names, adult labels, exports and APIs remain owner-only under the existing NAS and Cloudflare checks. No images are deleted, moved or sent to an outside AI service.

People tags and adult-content labels use their own channel revisions, idempotent receipts and undo history in the existing NAS SQLite database; meme labels and training remain independent. Lost-response retries survive reload; stale saves receive 409. Export history includes names, annotation states and reversible annotation events; the decision CSV still exports meme decisions only. Importing all organized images preserves the existing immutable 19,208-image catalog. Added Photos/Memes/Screenshots/Documents/Graphics/Technical review records use neutral placeholder scores and are excluded from learned-cutoff training because they did not receive the same refinement scoring pass. Unsupported originals without any usable thumbnail remain catalogued with unavailable previews and cannot be blindly reviewed.

Owner-only JSON POST routes: `people/create` with `{op,name}`, `people/decision` and `adult/decision` with `{op,sha256,revision,value}`, and the corresponding `/undo` routes with `{op,event}`. People values are `{state: tagged|none|skip, people:[tag IDs], other:boolean}`; adult values are `{state: adult|not_adult|skip}`. Queue parameters add `mode`, `people_state`, repeated `person`, and `adult_state`. API values and SQL filters are validated. `tests/test_annotations.py` and `tests/browser_annotations.cjs` cover combined filters, independent saves and undos, names, retries and exports. Synthetic QA fixtures stay outside releases.

## Automatic adult-content suggestions

Model: [Marqo/nsfw-image-detection-384](https://huggingface.co/Marqo/nsfw-image-detection-384), Apache-2.0, pinned revision `0c26ec22111b83f106d72a55f611ec35962bcb65`. This is a dedicated image classifier with NSFW/SFW outputs; it does not recognize people. The initial scan runs locally on the Windows GPU using the existing stripped JPEG previews, pinned safetensors weights, and the model's documented 384px center-crop preprocessing. A weight SHA256, label ordering, runtime versions and synthetic inference check are recorded outside the release. No private images go to Hugging Face or an external inference API. This initial full-collection scan is a one-off local job; future new-image scans require rerunning the local classifier. Saved suggestions and review queues live on the NAS and do not need this PC running.

Scores >=0.85 are **Likely adult**, <=0.15 **Likely not adult**, and intermediate scores **Uncertain**. The default private queue includes the first two review-relevant groups (likely adult and uncertain). These model scores are not calibrated probabilities for this personal collection. This broader NSFW model can flag non-sexual skin exposure or miss small/cropped explicit content; it is a review aid, not a verified X-rated verdict. Unsupported images remain unscanned. Owner labels always remain independent and editable; importing predictions never writes annotations or meme decisions.

Machine filters (`adult_ml=flagged|likely_adult|uncertain|likely_safe|unscored|all`) combine with existing person, band and manual-label filters. `sort=adult` puts highest NSFW scores first. Queue responses include aggregate scan counts and per-image suggestions; history exports include prediction provenance. Signed-owner-only `POST adult/import-predictions` accepts `{model,model_revision,items:[{sha256,media_sha,score}]}`, validates scores against the immutable ready preview hashes, and refuses a differing existing prediction atomically. Browser authentication cannot import machine labels. Weights, ML dependencies, logs and scan data remain outside the curated release. `tests/test_adult_ml.py` and `tests/browser_adult_ml.cjs` cover threshold boundaries, ranking, batch rollback, ownership, filters, persistence and independent manual corrections.
